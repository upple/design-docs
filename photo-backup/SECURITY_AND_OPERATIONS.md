# 보안 및 운영 정책

## 1. 위협 모델

보호 대상은 사진·동영상 원본, EXIF/GPS 메타데이터, 사용자 계정, refresh token, 관리자 작업 기록입니다. 주요 위험은 외부 무단 접속, 사용자 간 데이터 노출, 악성 파일 업로드, 비밀번호 공격, 디스크 마운트 오류, 파일/DB 상태 불일치 및 SSD 자체 고장입니다.

현재 SSD 암호화와 외부 사진 백업은 선택하지 않았습니다. 따라서 물리적 SSD 탈취나 SSD 자체 고장에 대한 보호가 제한됨을 운영 위험으로 명시합니다.

## 2. 외부 네트워크

- 공유기에서 Raspberry Pi로 TCP 80/443만 전달합니다.
- SSH, DB 포트, API 직접 포트, 관리자 전용 포트는 인터넷에 포워딩하지 않습니다.
- 공인 IPv4와 도메인 또는 무료 DDNS를 사용합니다.
- Caddy 자동 HTTPS는 외부 DNS와 필요한 포트 연결이 정상일 때만 성공합니다.
- 관리자 웹과 관리자 API는 정확한 가정 LAN CIDR에서만 허용합니다.
- 실제 LAN CIDR을 설치 시 설정하고 README/운영 설정에 기록합니다. RFC1918 전체를 무조건 허용하지 않습니다.
- 외부 요청의 관리자 경로는 프록시에서 거부하고 FastAPI에서도 관리자 역할을 확인합니다.
- FastAPI 포트는 공개 인터페이스에 바인딩하지 않습니다.
- NAT loopback이 없으면 내부 DNS override로 동일 도메인을 LAN IP로 해석하게 구성합니다.
- Caddy 앞에 다른 프록시가 없는 경우 원본 IP는 직접 연결 주소로 판단합니다. 전달 헤더를 무조건 신뢰하지 않습니다.

## 3. 비밀번호·토큰·세션

- Argon2id와 고유 salt로 비밀번호를 해시합니다.
- 비밀번호, 토큰, DB 비밀값을 Git에 저장하지 않습니다.
- 관리자 bootstrap secret은 최초 설치 시 제한된 권한의 환경 파일 또는 대화형 관리 CLI로 전달합니다.
- 최초 관리자 로그인에 비밀번호 변경을 강제합니다.
- access token 기본 수명은 15분, refresh session 기본 수명은 30일로 시작합니다. 운영 중 단축·조정할 수 있게 설정합니다.
- refresh token은 서버 DB에 해시로 저장하고 사용할 때 rotation합니다.
- 로그아웃·비밀번호 재설정·계정 정지에서는 관련 세션을 폐기합니다.
- 로그인 rate limit은 계정 및 IP 기반으로 적용합니다. 기본 초기값은 계정/IP 조합당 15분에 실패 5회부터 지연·제한하는 방식이며, 영구 잠금으로 쉽게 DoS가 발생하지 않게 합니다.
- 브라우저 관리자 세션은 Secure, HttpOnly 및 적절한 SameSite 쿠키를 사용합니다. 쿠키 인증 상태 변경 요청에는 CSRF 방어를 적용합니다.
- HTTPS에서 HSTS 등 헤더를 적용하되 도메인과 배포가 검증된 다음 활성화합니다.

## 4. 파일 업로드·다운로드 보안

- 파일명은 표시용 메타데이터로만 저장하고 경로 구성에는 사용하지 않습니다.
- 서버 생성 UUID를 저장 키로 사용합니다.
- 파일 시그니처와 실제 컨테이너를 검사하고 클라이언트 MIME 값은 참고용으로만 사용합니다.
- 이미지·동영상 파서 업데이트를 유지하고 파일 처리 오류를 안전하게 처리합니다.
- 임시 파일은 일반 자산 목록이나 다운로드 API에서 접근할 수 없습니다.
- 다운로드·미리보기·검색 모두 인증 사용자 owner_id 범위를 적용합니다.
- 파일 경로는 DB에서 조회한 서버 내부 키로만 결정하며 사용자 입력 경로를 결합하지 않습니다.
- 파일을 전체 메모리에 읽지 않고 청크 스트리밍합니다.
- Range 요청과 캐시 헤더가 인증 우회를 만들지 않도록 사용자 인증 및 비공개 캐시 정책을 적용합니다.
- GPS/EXIF, 원본 경로, 비밀번호, 토큰을 로그에 남기지 않습니다.

## 5. SSD 마운트 안전

- 외장 SSD를 UUID 기반으로 /srv/photo-data에 마운트합니다.
- API 컨테이너에 필요한 하위 경로만 명시적으로 마운트합니다.
- systemd 서비스는 해당 마운트가 실제로 존재한 뒤 시작하도록 설정합니다.
- 부팅 시 마운트 검사를 수행하고, 마운트 대상이 아닌 일반 디렉터리에 사진을 저장하지 않도록 guard를 둡니다.
- 파일 생성·이동·삭제 API는 실행 직전에 SSD 마운트 상태와 파일시스템 여유 공간을 재확인합니다.
- 장치가 제거되거나 I/O 오류가 발생하면 업로드와 삭제를 중단하고 관리자 UI 및 로그에 오류를 기록합니다.
- SSD는 현재 암호화하지 않으므로 물리적 접근 통제와 디렉터리 권한이 필요합니다.

## 6. 저장 공간 정책

- 사용자 할당량: 300,000,000,000바이트
- 80%에서 경고
- 사용자 한도 초과 시 신규 업로드 차단
- 전역 여유 공간이 15% 미만 또는 100GB 미만이면 신규 업로드를 차단
- 기존 조회·다운로드·삭제·휴지통 정리는 계속 허용
- 용량 경고는 관리자 페이지와 서버 로그에 기록
- 모바일 대용량 전송 경고 기본 임계값은 100MiB로 시작하고 추후 설정 가능하게 함
- 파일 크기별 고정 제한은 두지 않지만, 프록시 request body limit이 API 요청을 제한하지 않도록 설정 검증을 수행

## 7. 백업·복구

- SQLite DB는 매일 안전한 백업 방법으로 백업하고 최근 7일분을 보관합니다.
- 백업 스크립트는 종료 코드·결과 파일 크기·SQLite 무결성 검사 등을 확인합니다.
- 월 1회 백업 사본을 별도 임시 위치에 복원하는 테스트를 권장합니다.
- 같은 SSD에 저장된 DB 백업은 SSD 자체 고장·분실 시 복구할 수 없습니다.
- 사진 원본의 외부 백업은 요구사항상 제공하지 않습니다. SSD 손실은 사진 영구 손실로 이어질 수 있습니다.
- 복원 시 DB에 등록된 파일과 실제 파일을 대조하고 불일치 후보를 관리자에게 표시합니다.

## 8. 유지보수 및 장애 처리

- 관리자 화면에서 API 상태, DB 연결, SSD 마운트 여부, 전체 여유 공간, DB 백업 시각·결과를 표시합니다.
- 외부 알림 서비스는 사용하지 않으므로 완전한 서버 종료는 실시간 알림을 보내지 못합니다.
- 감사 로그 기본 보존은 90일입니다. 보존 정책은 설정할 수 있게 구현합니다.
- 보안 업데이트는 정기적으로 적용하고 배포 전 DB 백업 및 롤백 절차를 확인합니다.
- SQLite 스키마 변경은 버전 관리 migration으로 수행합니다.
- 정리 작업은 반복 실행해도 데이터가 일관되도록 멱등성을 확보합니다.
