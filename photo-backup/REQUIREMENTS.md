# 요구사항 명세

## 1. 사용자 및 환경

- 사용자 수: 가족·부부 등 2~5명
- 서버: Raspberry Pi 5, RAM 8GB, Ubuntu, 외장 SSD 2TB
- 외부 접속: 공인 IPv4로 외부 모바일 네트워크에서도 앱 사용
- 관리자 접속: 동일 내부 네트워크에 한정
- 앱 배포: 개인용 설치. Android APK 직접 배포, iOS 무료 개발자 서명 방식의 제약 수용
- 운영 비용: 무료 우선
- 사진 공유: MVP 제외
- 자동 백업: MVP 제외. 사용자가 앱에서 파일을 선택해 수동 업로드

## 2. 계정 및 인증

- REG-01: 사용자는 사용자 ID와 비밀번호로 가입을 신청할 수 있습니다.
- REG-02: 신규 계정 상태는 pending이며 관리자가 승인하기 전에는 로그인할 수 없습니다.
- REG-03: 관리자는 가입을 승인하거나 거절할 수 있습니다.
- REG-04: 관리자 계정은 설치 시 한 번 생성하고 공개 회원가입으로 생성할 수 없습니다.
- REG-05: 관리자 초기 비밀번호는 최초 로그인 시 변경해야 합니다.
- REG-06: 일반 사용자 비밀번호는 관리자가 재설정할 수 있으며, 임시 비밀번호는 다음 로그인 시 변경해야 합니다.
- REG-07: 비밀번호 원문은 저장하거나 로그에 기록하지 않습니다.
- REG-08: 계정은 active, pending, suspended, archived 상태를 사용합니다.
- REG-09: 계정 정지·보관은 로그인 및 접근을 차단하되 사진 원본은 기본적으로 보존합니다.
- REG-10: 로그인 시도 제한과 세션 폐기 기능을 제공합니다.

## 3. 사진·동영상 기능

- MED-01: 갤러리와 파일 앱에서 사진·동영상을 선택해 업로드할 수 있습니다.
- MED-02: 여러 파일 업로드를 지원하고 파일별 진행률과 실패 이유를 표시합니다.
- MED-03: 네트워크 중단 또는 앱 재시작 후 미완료 업로드를 이어서 수행할 수 있습니다.
- MED-04: 원본 바이트를 그대로 보존하고 서버에서 자동 압축·변환하지 않습니다.
- MED-05: 미리보기 이미지는 별도 파일로 생성하며 원본과 분리합니다.
- MED-06: SHA-256 해시로 동일한 파일을 감지합니다. 감지는 사용자 단위로 한정합니다.
- MED-07: 중복 발견 시 기본적으로 업로드를 건너뜁니다. 사용자가 선택하면 별도 자산으로 저장할 수 있습니다.
- MED-08: 사진은 날짜별로 탐색하고 파일명, 촬영 날짜, 카메라 제조사·모델, GPS 메타데이터를 조회할 수 있습니다.
- MED-09: 사용자는 직접 앨범을 생성·수정·삭제하고 자산을 앨범에 추가·제거할 수 있습니다.
- MED-10: 동영상은 가능한 경우 앱에서 스트리밍하고 원본 다운로드도 지원합니다.
- MED-11: 스트리밍 시 HTTP Range 요청을 지원해 재생 위치 이동을 허용합니다. 코덱 호환성은 기기별로 다를 수 있습니다.
- MED-12: 여러 파일을 선택해 일괄 다운로드 대기열에 등록할 수 있습니다.
- MED-13: 다운로드한 사진·동영상은 휴대폰 기본 사진 보관함(갤러리)에 저장합니다.
- MED-14: 모바일 데이터 업로드를 허용하되 대용량 전송 전에 경고합니다.
- MED-15: 서버 내 미리보기·원본·휴지통을 각각 처리하며, 서버 작업으로 휴대폰 원본을 삭제하지 않습니다.

## 4. 삭제·복원·중복 정책

- DEL-01: 휴대폰 기본 사진 앱에서 삭제해도 서버 사진은 유지합니다.
- DEL-02: 서버에서 삭제한 사진은 30일간 휴지통에 보관합니다.
- DEL-03: 휴지통 내 파일은 사용자 한도 계산에 포함합니다.
- DEL-04: 휴지통 복원은 파일 원본이 정상적으로 존재할 때만 성공합니다.
- DEL-05: 30일 경과한 파일은 원본·미리보기·관련 메타데이터를 영구 삭제합니다.
- DEL-06: 사용자 계정 삭제·보관은 기본적으로 계정 접근만 차단하고 사진은 보존합니다.
- DEL-07: 앨범 삭제는 앨범과 항목 관계만 제거하고 원본 자산을 삭제하지 않습니다.

## 5. 용량·검색

- STO-01: 사용자별 기본 한도는 300,000,000,000바이트(십진 300GB)입니다.
- STO-02: 사용량 80% 이상에서 경고합니다.
- STO-03: 사용자의 한도에 도달하면 신규 업로드를 차단합니다. 조회·다운로드·삭제는 계속 허용합니다.
- STO-04: 업로드 시작 시 예상 크기를 예약하여 동시 업로드로 한도를 넘지 않게 합니다.
- STO-05: 파일 크기별 고정 제한은 두지 않습니다. 실제 한도, 전체 여유 공간 및 업로드 세션 정책으로 제어합니다.
- STO-06: 전체 SSD 여유 공간이 15% 미만 또는 100GB 미만이면 신규 업로드를 차단합니다.
- STO-07: 사용자별 동일 파일 해시 감지를 수행하며 다른 사용자의 해시나 존재 여부를 노출하지 않습니다.
- STO-08: 파일 검색과 목록은 모든 경우에 owner_id 범위로 제한합니다.

## 6. 관리자 기능

- ADM-01: 가입 대기 계정 승인·거절
- ADM-02: 계정 활성화·정지·보관
- ADM-03: 일반 사용자 비밀번호 재설정
- ADM-04: 사용자별 용량·할당량 및 전체 디스크 사용량 확인
- ADM-05: 인증 실패와 관리자 작업 감사 로그 확인
- ADM-06: API, DB, 마운트, 저장 공간 상태 확인
- ADM-07: 디스크 부족, 마운트 오류, DB 백업 실패를 관리자 화면과 서버 로그에 표시
- ADM-08: 관리자 웹과 API는 내부 네트워크에서만 접근 가능
- ADM-09: 기본 관리자 UI는 사진 콘텐츠를 열람·다운로드하는 기능을 제공하지 않습니다.

## 7. 비기능 요구사항

- NFR-01 보안: 인터넷 구간은 HTTPS로 암호화합니다.
- NFR-02 격리: 모든 자산·앨범·업로드 세션 조회에서 서버 측 소유권 검증을 수행합니다.
- NFR-03 무결성: 업로드 완료 시 서버 SHA-256과 파일 크기를 검증합니다.
- NFR-04 복원: SQLite DB를 매일 백업해 최근 7일분을 유지합니다.
- NFR-05 저장소 안전: 외장 SSD 미마운트 시 파일 변경 API를 실패 처리합니다.
- NFR-06 운영: Ubuntu 재부팅 후 마운트 검사 뒤 서비스가 시작되도록 구성합니다.
- NFR-07 비용: 초기 운영에 유료 클라우드 또는 이메일 알림 서비스가 필요하지 않도록 합니다.
- NFR-08 관측성: 주요 인증·관리자 작업과 저장소 오류를 기록하되 토큰·비밀번호·파일 원문을 로그에 남기지 않습니다.
- NFR-09 유지보수: 스키마 마이그레이션, 복원 테스트, SSD 여유 공간 감시를 운영 절차에 포함합니다.

## 8. MVP에서 제외하는 기능

자동 카메라 롤 백업, 공유 앨범 및 공개 링크, 외부 클라우드 사본, AI 분류·얼굴 인식, 사진·동영상 재인코딩, 다중 서버, 웹에서 사진 원본 편집은 MVP 범위에 포함하지 않습니다.
