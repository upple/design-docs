# 요구사항 명세

## 1. 환경 및 플랫폼

- 사용자 수: 가족·부부 등 2~5명
- 서버: Raspberry Pi 5, RAM 8GB, Ubuntu, 외장 SSD 2TB
- Android: Flutter 네이티브 앱
- iOS: 반응형 웹앱(PWA). Safari에서 홈 화면에 추가해 사용하며 네이티브 IPA를 만들지 않음
- 관리자: 별도 React 웹앱. 내부 네트워크에서만 접근
- 외부 접속: 공인 IPv4 및 HTTPS를 통한 모바일 데이터/Wi-Fi 접속
- 운영 비용: 무료 우선
- 자동 카메라 롤 백업: MVP 제외, 수동 파일 선택 업로드
- 사진 공유: MVP 제외

## 2. 계정 및 인증

- REG-01: ID·비밀번호로 가입 신청. 신규 계정은 pending
- REG-02: 관리자가 승인하기 전에는 일반 사용자 로그인 불가
- REG-03: 관리자는 가입 승인·거절, 계정 활성화·정지·보관 가능
- REG-04: 관리자 계정은 설치 시 별도 bootstrap 절차로 생성하며 공개 가입으로 만들 수 없음
- REG-05: 최초 관리자 로그인 시 비밀번호 변경 강제
- REG-06: 관리자는 일반 사용자 비밀번호를 재설정할 수 있으며 다음 로그인 시 변경 강제
- REG-07: 비밀번호 원문은 저장하거나 로그에 기록하지 않음
- REG-08: 계정 상태는 pending, active, suspended, archived
- REG-09: 정지·보관 상태에서는 접근을 차단하되 사진은 기본 보존
- REG-10: 로그인 시도 제한, 세션 폐기, 비밀번호 변경 후 기존 세션 무효화
- REG-11: Android 네이티브 앱은 짧은 수명 access token + 회전 refresh token
- REG-12: iOS PWA는 same-origin HttpOnly Secure 쿠키 세션과 CSRF 방어
- REG-13: 관리자 웹은 별도 host-only 쿠키와 별도 관리자 로그인·세션

## 3. 사진·동영상

- MED-01: 사진·동영상을 갤러리/사진 선택기 및 파일 선택기로 수동 업로드
- MED-02: 여러 파일 선택, 파일별 진행률·실패 원인 표시
- MED-03: 서버 측 청크 업로드 세션과 재개 API 제공
- MED-04: 서버는 수신한 파일 바이트를 원본으로 보존하고 자동 압축·변환하지 않음
- MED-05: 세션 생성 전 클라이언트가 메모리에 전체 파일을 올리지 않고 incremental SHA-256을 계산하고, 서버가 독립 계산한 해시 및 크기와 대조
- MED-06: 미리보기는 별도 파일로 생성
- MED-07: 동일 사용자 내 SHA-256 중복 감지. 기본 건너뛰기, 선택 시 별도 자산으로 저장
- MED-08: 촬영 날짜, 파일명, 카메라 제조사·모델, GPS 메타데이터 검색
- MED-09: 날짜별 탐색 및 사용자 지정 앨범
- MED-10: 동영상 스트리밍과 원본 다운로드, 지원되는 환경에서 HTTP Range 탐색
- MED-11: 모바일 데이터 업로드 허용. 대용량 전송 전에 경고
- MED-12: 서버에서 삭제해도 휴대폰 원본을 삭제하지 않음
- MED-13: 휴대폰 사진 앱에서 삭제해도 서버 백업은 유지
- MED-14: 다른 사용자의 파일·해시 존재 여부를 노출하지 않음

## 4. 플랫폼별 선택·업로드·다운로드

- PLAT-01 Android: Flutter 앱에서 갤러리/파일 선택, 다운로드 후 기본 미디어 라이브러리에 저장
- PLAT-02 iOS: PWA의 파일 선택기를 통해 Photos/Files에서 업로드. 서버는 웹 선택기가 전달한 바이트를 보존
- PLAT-03 iOS PWA가 사진 보관함의 모든 원본 리소스, Live Photo 쌍, iCloud 원본을 항상 그대로 반환한다고 가정하지 않음. HEIC·MOV·대용량 파일은 실기기 검증
- PLAT-04 iOS PWA는 화면에서 시작하는 수동 업로드. 페이지 종료/OS 일시 중단 후 백그라운드 전송이 계속된다고 보장하지 않음
- PLAT-05 PWA 재실행 후 브라우저가 파일 참조를 유지하지 않으면 같은 파일을 다시 선택해야 합니다. 재선택 파일의 incremental SHA-256이 세션의 expected_sha256와 일치할 때만 재개합니다.
- PLAT-06 Android는 여러 파일을 순차 다운로드해 갤러리에 저장
- PLAT-07 iOS PWA 단일 파일은 기본적으로 Files/다운로드에 저장합니다. 크기가 작은 파일은 navigator.canShare 검사 후 지원되는 공유 시트를 제공할 수 있지만, Photos 저장 대상의 표시·선택을 보장하지 않습니다.
- PLAT-08 iOS PWA 여러 파일은 ZIP으로 Files에 내려받고 사용자가 추출·사진 앱으로 가져옴. PWA가 Photos에 직접 일괄 쓰는 것으로 약속하지 않음
- PLAT-09 브라우저 저장소에는 세션 복구용 ID·오프셋만 저장. 토큰은 localStorage/IndexedDB에 저장하지 않음
- PLAT-10 PWA service worker는 정적 셸만 캐시하며 개인 사진·동영상·인증 응답은 캐시하지 않음
- PLAT-11 iOS PWA 업로드 진행 중 Screen Wake Lock API를 요청하여 화면 자동 잠금에 따른 세션 중단을 방지하고 UI에 '화면 켜짐 유지' 상태를 안내함
- PLAT-12 iOS PWA 대용량 미디어 사전 해시는 WebAssembly(Wasm) 가속 스트리밍 SHA-256 라이브러리(hash-wasm 등)를 적용하여 연산 시간과 배터리 소모를 최소화함
- PLAT-13 iOS PWA 다중 다운로드(ZIP) 완료 시 사용자가 Files 앱에서 사진 보관함으로 쉽게 가져올 수 있도록 3단계 시각적 가이드 모달(Files 열기 → 압축 해제 → 사진 저장)을 제공함

## 5. 삭제 및 복원

- DEL-01: 서버에서 삭제하면 30일간 휴지통에 보관
- DEL-02: 휴지통 자산도 사용자 용량에 포함
- DEL-03: 30일 후 시스템 정리 작업이 영구 삭제. 일반 사용자용 즉시 영구 삭제 API는 제공하지 않음. 삭제 작업은 중단·재시작 후 재개 가능
- DEL-04: 영구 삭제는 purging 상태/작업을 거쳐 파일시스템·DB 불일치를 복구 가능하게 함
- DEL-05: 앨범 삭제는 관계만 삭제하고 원본 자산은 유지
- DEL-06: 계정 보관·정지는 접근만 차단하고 사진 보존

## 6. 사용자 한도 및 저장 공간

- STO-01: 사용자별 기본 한도 300,000,000,000바이트(십진 300GB)
- STO-02: 사용량 80% 도달 시 경고
- STO-03: 한도 도달 시 신규 업로드 차단. 조회·다운로드·삭제는 허용
- STO-04: 업로드 세션 생성 시 전체 크기를 예약해 동시 업로드로 한도 초과 방지
- STO-05: 원본 업로드에 파일별 고정 크기 제한은 없음. 청크는 8MiB, HTTP 요청 본문 제한은 청크보다 조금 크게 설정
- STO-06: 전체 SSD 여유 공간이 전체 용량의 15% 또는 100GB 중 더 큰 값보다 작으면 신규 업로드·내보내기 작업 차단
- STO-07: ZIP 내보내기는 예상 크기를 예약하여 임시 ZIP이 SSD 여유 공간을 위험 수준으로 낮추지 않도록 함

## 7. 관리자 기능

- ADM-01 가입 승인·거절
- ADM-02 사용자 활성화·정지·보관
- ADM-03 일반 사용자 비밀번호 재설정
- ADM-04 사용자별 용량 및 전체 디스크 확인
- ADM-05 인증 실패와 관리자 작업 감사 로그
- ADM-06 API, DB, SSD 마운트, DB 백업 상태 표시
- ADM-07 디스크 부족·마운트 오류·백업 실패 경고
- ADM-08 관리자 웹/API는 별도 관리자 호스트에서 실제 LAN CIDR에만 허용
- ADM-09 관리자 UI에서 사진을 열람·다운로드하는 기능은 MVP 제외
- ADM-10 디스크 90% 초과, 외장 SSD 탈락, DB 백업 실패 등 치명적 운영 장애 발생 시 Telegram/Discord 무료 웹훅으로 관리자에게 즉시 알림 발송

## 8. 비기능 요구사항

- NFR-01 외부 통신은 HTTPS
- NFR-02 모든 자산·앨범·업로드·내보내기 요청에서 서버 측 소유권 검증
- NFR-03 서버 SHA-256 무결성 검증
- NFR-04 SQLite 백업 매일, 최근 7일 보존
- NFR-05 외장 SSD 미마운트 시 파일 생성·이동·삭제 금지
- NFR-06 마운트 검사 후 서비스 시작
- NFR-07 감사 기록에 비밀번호·토큰·GPS·원본 경로를 남기지 않음
- NFR-08 PWA의 개인 미디어 캐시 금지
- NFR-09 CI에서 API·웹 빌드를 재현 가능하게 구성
- NFR-10 iOS PWA 실기기 테스트 포함
- NFR-11 라즈베리파이 원클릭 대화형 설치 스크립트(deploy/setup.sh)로 TTHW < 10분 온보딩 지원
- NFR-12 로컬 PC에서 즉시 테스트 가능한 Docker Compose 프로필(deploy/docker-compose.dev.yml) 제공
- NFR-13 SQLite 일일 백업은 온라인 백업 API(.backup)를 적용해 WAL 복사 손상 방지
- NFR-14 Pillow/FFmpeg 백그라운드 썸네일 워커는 동시성 1개 제한 및 nice 19로 실행하여 라즈베리파이 5 부하 방지

## 9. MVP 제외

자동 사진 백업, 공유 앨범·공개 링크, 외부 사진 사본, AI 분류·얼굴 인식, 동영상 재인코딩, 다중 서버, 네이티브 iOS IPA 및 오프라인 사진 라이브러리는 MVP 범위 밖입니다.
